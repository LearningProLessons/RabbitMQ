# 🧾 Payment Gateway Routing with RabbitMQ (Direct Exchange)

این پروژه یک مثال ساده و کاربردی از استفاده‌ی RabbitMQ با مدل **Routing (Direct Exchange)** توی دنیای واقعی پرداخت (مثل
پرداخت‌یارها و درگاه‌های ایرانی) رو پیاده‌سازی می‌کنه.

---

## 📦 سناریو

فرض کن ما یه سرویس پرداخت داریم که به چند درگاه وصل شده:

- زرین‌پال (`zarinpal`)
- آیدی‌پی (`idpay`)
- پی‌پینگ (`payping`)
- زیبال (`zibal`)

کاربر توی سایت ما درگاه مورد نظر خودش رو انتخاب می‌کنه. حالا می‌خوایم وقتی درخواست پرداخت ساخته شد، اون پیام فقط بره سمت
**سرویس مخصوص همون درگاه**.

---

## 🧠 چرا از RabbitMQ Routing استفاده کردیم؟

ما از **Direct Exchange** استفاده کردیم چون:

- هر پیام باید فقط به **یک سرویس خاص** بره
- هر سرویس فقط پیام‌های مربوط به خودش رو دریافت کنه
- سیستم‌مون **loosely coupled** و قابل **گسترش‌پذیر** باشه

---

## ⚙️ ساختار RabbitMQ

- **Exchange:** `payment-gateway-routing-exchange` (نوع: `direct`)
- **Queues:**
    - `idpay-queue`
    - `zarinpal-queue`
    - ...
- **Routing Key برای هر درگاه:**
    - `"idpay"`
    - `"zarinpal"`
    - `"payping"`
    - `"zibal"`

---

## 👷‍♂️ ساختار پروژه

### 1. Producer (ارسال پیام):

کدی که توسط سیستم اصلی اجرا می‌شه و پیام پرداخت رو با توجه به درگاه انتخاب‌شده ارسال می‌کنه.

مثال:

```csharp
routingKey = "idpay"
message = { OrderId = "ABC123", Amount = 150000 }
````

→ پیام فقط به `idpay-queue` می‌ره.

---

### 2. Consumer (مصرف پیام):

سرویس مخصوص هر درگاه، پیام‌های مربوط به خودش رو مصرف می‌کنه.

مثلا:

* `idpay-queue` فقط پیام‌هایی با Routing Key `idpay` رو می‌گیره.
* `zarinpal-queue` فقط پیام‌هایی با Routing Key `zarinpal` رو می‌گیره.

---

## 🔄 گسترش پروژه

برای اضافه کردن درگاه جدید:

1. یه Queue جدید تعریف کن (مثلاً `saman-queue`)
2. یه Routing Key براش مشخص کن (مثلاً `saman`)
3. یه Consumer جدید براش بنویس و وصلش کن به همون Queue و Routing Key

## 📌 نکات پایانی

* Routing باعث می‌شه پیام‌ها فقط به جایی که باید برن، برسن → بهینه‌تر و سریع‌تر
* هر درگاه پرداخت، مثل یه سرویس جدا عمل می‌کنه → قابل تست و توسعه مستقل
